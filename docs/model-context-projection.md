# 模型上下文投影与权威边界

本阶段对齐 Maka 的交互语义边界：Runtime Event Log 是 agent 交互事实的权威来源。UI 会话和模型历史是不同投影。新的模型请求以历史投影为输入，再结合本次系统提示、技能、记忆检索、当前输入、工具定义和请求参数。

不把整个项目改成事件溯源，也不把一次历史请求的重建当成继续执行的许可。

## 事实所有权

| 数据 | 权威来源 | 派生或关联方式 |
|---|---|---|
| 已接纳输入、执行身份、终态 | `request.accepted`、`run.*` | 保留 root / session / turn / run / epoch 身份 |
| 完整模型输出、原生协议状态、模型工具调用 | `model.response.recorded` | 后续步骤重新读取已提交的输出；内部记忆、路由等模型调用不进入对话历史 |
| 模型可见工具结果 | `interaction.tool_result` | 关联逻辑模型调用和该步工具调用 ID；物理工具派发和结果仍由 `tool.dispatched/returned` 记录 |
| 会话呈现、显式编辑和删除、旧历史导入 | `conversation.baseline/changed` | 原样呈现的用户或模型文本引用原事实；经解析的呈现内容有明确的执行来源。不是另一份模型执行结论 |
| 当次请求所选表示及环境输入 | `model.context.observed`、`model.request.prepared` | 按字段、消息、工具定义内容寻址；引用历史选取和本执行交互事实。它们描述模型当时看到了什么，不取代原始交互语义 |
| UI SQLite、内存 Session、上下文缓存 | 可重建投影 | 不能决定已提交的历史；模型历史读取日志，缓存删除不影响请求重建 |
| 收发队列、待办、调度、配置、凭据 | 各自领域存储 | 本轮保留其所有权。队列通过稳定队列 ID、执行 ID、派发回执关联；待办变化仍由工具结果和主动候选关联说明，不复制一份待办权威状态到日志 |

已有 pending-chat 文件继续承担“待补存写入意图”的职责，以稳定写入 ID 补交会话事实；会话事实提交后视图失败，通过日志重放恢复。跨进程补存使用原 `execution_request_id`、来源和 Session 关联已接纳执行，仍可引用原模型结果。它不是已完成模型调用的权威，也不授权重复调用模型。

## 生产路径

1. 普通对话的检索历史和实际推理历史均通过 `read_committed_history` 从已提交事件生成。新模型步骤保留原生 Provider 字段、工具调用顺序和结果。旧记录采用原有会话事实兼容投影，不伪造旧模型调用。
2. Prompt/技能/记忆/Hook/裁剪仍决定本次请求的表示。Provider 完成协议转换后，将实际使用的消息、工具和参数冻结为不可变组件，再提交有序选取清单。
3. 上述组件与清单在同一 SQLite 事务中提交。清单绑定先前执行事件的摘要，并保留历史选取与交互来源。`project_model_context` 从这个前缀重建请求。
4. Chat Completions 和 Codex Responses 的真实传输消费投影器返回值，而不是旁路使用原始调用参数。认证头与凭据由传输层另行提供，不写入上下文事实。
5. 物理网络重试保留同一个逻辑调用和输入前缀，只增加 attempt 事实。模型完整返回必须提交后才能交给工具循环。工具结果进入下一轮前也要提交语义事实。
6. 流式增量不等于完整返回。缺少结束标记、被截断或被过滤的流不产生成功模型结果；非流式响应的长度截断和内容过滤也不能进入工具派发。

Runtime 启动时将所有模型 Provider 绑定到同一日志。没有外层执行的后台模型工作获得独立执行身份；普通聊天、后台子任务和主动流程保留已有执行边界。库级无 Host 调用仍可使用纯投影，但不声称具备持久恢复能力。

异步观察队列与 Markdown 记忆维护在每次入队时分离执行上下文，保留原执行的 root / turn 关联。后台模型工作拥有独立终态，不能继承已回复会话的终态责任，也不能让后续入队事件沿用第一条事件的执行身份。同步等待的模型、工具与主动流程仍属于原执行，未知工具结果的保护不变。

## 历史与请求是两种投影

`interaction_history` 生成可用于新请求的交互历史；它不把内部记忆总结塞进聊天。未取得完整工具结果的步骤保留原事实，并产生 `unresolved_tool_step_excluded` 诊断，不能用虚构的成功结果补齐。既有 `needs_review` 与人工处置规则不变。

`model_context(turn_id, call_id, through_seq, expected_digest)` 重建某次已经记录的实际请求。它不再读取当前提示词、技能、配置或工具注册表，也不调用 Provider。`execution.context` 在本地 Bridge 和已认证远程 Host 中提供相同的只读入口。未记录过请求的旧执行明确返回 `not_recorded`。

内容摘要、顺序、版本或来源缺失时拒绝重建。对同一前缀重复投影没有模型、工具、队列或网络副作用。

## 崩溃一致性

- 请求提交失败：事务回滚，不请求模型。
- 请求已提交但结果未提交：恢复为中断，不推断模型是否收到，也不自动重发。
- 模型响应落盘失败：执行被隔离，禁止后续工具操作。
- 工具已派发但回执不明：继续保留未知结果和 `needs_review`，重建不改变其结论。
- 会话事实引用模型结果时，模型事实已先提交；会话事实先于 UI 视图提交。视图失败可重复重建，不重复调用模型。
- 队列和待办的提交、去重与恢复规则仍属于其已有领域。本轮没有引入跨数据库的虚构原子事务，也没有引入第二个发送者。

## 验收

硬标准：真实 Provider 发送测试请求后，删除上下文缓存，修改测试提示词、技能和模型配置，关闭并重开日志，再用原事件前缀和摘要重建，得到与原请求一致的内容。另有投影输出替换测试，证明实际传输使用投影器的返回值。

回归覆盖两种 Provider 协议、原生推理状态、部分流、旧历史、UI 缓存污染、认证远程读取，以及真实子进程在请求提交、网络调用、模型返回、工具结果和发送回执边界崩溃。恢复和重复重放只读取事实，不增加模型、工具或发送计数。

本轮不实现中断点自动续跑、自动重新生成历史摘要、服务端部署或全项目状态事件化。保持本地与远程模式、300 秒主动轮询及现有配置。

后续已补充[受控续跑 v1](architecture/controlled-continuation-v1.md)：只读计划、用户确认、
重新校验和持久唯一领取后创建关联新执行。它消费已提交历史组装下一步请求，
不会重新发送本页描述的历史请求；未知结果仍然阻止续跑，也不启用自动续跑。
