# P0a / P0b / P1 生产真实链路补充验收

本报告补充已有 P0a 生产及 Telegram 报告。目标运行代码为 `a573804ae04a6a826667dca00bd4b338d50a3777`，包含 PR #51 恢复修复和 PR #52 运行中维护保护；验收开始时 master 为仅补充文档的 `e8c7511`。

## 方法与范围

- 从真实 Telegram Desktop 的 kaze 聊天发送两条验收消息。普通任务仅计算公开数字 `7+11+13+17`，取消任务仅计算平方和；不发送本地路径或配置，不要求模型修改长期记忆。
- Goal 没有在线管理 RPC。Host 空闲后优雅停止并冷备份，通过部署版本的 GoalStore / GoalInputs 创建独立验收目标与持久化输入，随后启动原生产 Host。只有准备数据使用维护脚本；执行使用生产 GoalSubagentExecutor 和真实模型，验收使用固定 JSON 与命令校验器。
- P1 输入为维护入口注入的受控 timer 类型事实，覆盖两项批次、精确重放、字段不变的新版本、乱序旧版本及取消后输入。它不是实际定时器触发或真实 Wake 事件验收。
- Telegram 与 Goal 在同一生产 Host 上分别运行；当前产品没有 Telegram 自动创建 Goal 的入口，不将两条链路描述为 Telegram 自动建 Goal 的端到端闭环。
- 生产使用优雅重启，不故意制造验证命令失联或强杀 Host。PR #51 的未知命令恢复围栏仍以已有回归测试证据为准。本轮 Goal 取消覆盖等待阶段撤销后不执行；运行中取消由真实 Telegram 后台任务覆盖。
