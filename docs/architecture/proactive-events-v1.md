# 主动执行事实与可重建状态

在已有执行日志中接入 Kaze 的主动入口，覆盖 `wake` 和 `default` 生命周期。
独立 Host 与桌面本地 bridge 使用同一入口，远程客户端沿用执行及队列 RPC。
没有部署服务、迁移生产数据或修改配置。Wake 常规轮询及异常等待保持 300 秒；
已有多条 alert 的短间隔排空规则保留，待核对时不会继承上次的短间隔。

## 事实与投影

- `request.accepted` 接纳 `source=proactive` 的 tick，保留生命周期、渠道和目标。
  相同请求标识只读取已保存结果；中断、失败及待核对记录不重新运行回调。
- 插件门控及生命周期模块在执行前写 `proactive.stage.started`，完成后写
  `proactive.stage.completed`。`proactive.observed` 保存门控理由、候选身份、
  路由、决策、正文、证据、发送结果和入队标识。Wake 的决策模块内部包含多个阶段，
  模型与发送边界另有细分事实。
- `proactive.model.requested/returned` 记录逻辑模型调用身份、模型、输入摘要、
  返回内容/工具调用或错误类型。摘要仅供审计，不是完整模型上下文快照，不能据此续跑。
- 模型前以来源、候选类型及事件版本接纳候选，写 `proactive.candidates.claimed`。
  `proactive_claims` 是同一事件库中的可重建索引，不是第二份事实源。
  失败、已完成及已结束处置的候选不会被下一次轮询换一个 tick ID 再次处理。
  Context 用观察值摘要区分实际变化；没有稳定 ID 的候选也使用内容摘要。
- 用户在模型工作期间发言、发送前门控明确拒绝且没有入队/派发时，写
  `proactive.candidates.released` 释放候选，保留暂缓事实；未来安静的新轮次可再处理。
  旧 tick 的重放仍不调用模型。已经入队、关联队列或派发的尝试不能走此释放路径。
- MCP、外部工具、发送及成功后回调在原 execution scope 中记录。
  日志写入失败或未知外部结果会阻止后续模型调用和发送，不能由插件吞掉错误后继续。

执行投影中 `proactive` 保存阶段、模型调用、观察和候选。重建仅投影已提交事实，
不调用模型、不入队、不 ACK、不执行任何工具。损坏或不完整的事件前缀拒绝重建。
原有会话/执行事件兼容；不要用不认识新增事件的旧版本写入升级后的工作区。

## 队列与会话关联

主动决策和 delivery ID 在发送前记入日志。新 Outbox 意图与执行关联同队列事务提交；
复用原投递意图也关联当前执行。物理发送记录原有派发/返回事实，成功分段和平台回执
仍由队列保存。既有会话提交事实携带执行 ID，历史恢复继续按 delivery ID 去重。

事件库与队列没有跨库事务。入队成功、关联成功但后续观察事实未提交时，队列仍保留
真实意图和关联；事件重放不能据缺失的观察重复入队。工作台通过既有接口关联查询，
不会伪造入站消息：主动提醒通常只有发件任务，没有 Telegram Inbox。

普通对话与主动执行使用不同的活动占用约束，主动模型等待不会阻塞用户聊天。
原有用户活动检查、ChatLane 发送协调和目标身份校验保留。

## 崩溃恢复与人工处置

- 重启先按既有 epoch 锁恢复执行。没有未知外部结果的未完成尝试为 interrupted；
  有未确认外部结果为 needs_review。
- 这些记录未结束处置前，该会话的主动轮询保持等待，不新跑一轮模型来绕过恢复状态。
  普通对话不受此门控阻塞；主动 Outbox 的重启恢复须遵守下述受控恢复协议。
- [Phase B 受控恢复](proactive-recovery-v1.md) 已取代主动队列无条件自动发送：
  查看只读计划、确认、重新验证后才继续原意图。已成功分段读取回执，
  未保存回执的已派发分段保持 needs_review。重放执行事件本身从不发送。
- 只有决策事实、尚未入队时不会自动补造投递，也不会自动重新询问模型。
  在工作台检查原决策并处置。主动来源不开放整轮重试按钮。
- 结束执行处置不关闭关联队列、不伪造回执；应分别核对。结束处置不再释放同一候选，
  新版本候选仍可接纳。已有合法边界的续接通过关联新执行完成，不重跑原模型。
- ACK 异常同样保留待核对记录。确认发送、消费状态和原源的 ACK 情况后再结束处置；
  ACK 派发前持久标记、完成后保留收条；未知 ACK 不自动重试，不通过重新发送消息修复。

## 验证

`test_proactive_event_recovery.py` 启动真实 Python 子进程，使用真实 AppRuntime、Kernel、
Journal、Outbox、会话投影，只替换模型和外部发送/源边界。通过 `os._exit(73)` 在以下
位置退出：模型前、模型返回后、决策后、入队后、外部发送后但回执未知、分段回执后、
队列完成后、执行完成后。每个场景启动两次新进程并重复重放，比较模型/发送计数、
消息 ID、队列、关联和事件数量。

补充回归覆盖日志失败、取消、候选索引丢失、非法事件前缀、普通聊天并发，以及认证
远程 RPC 的查询/处置。隐藏 Electron 使用实际 Renderer、preload 与 Python 后端验证
主动事件可见、队列双向跳转、禁用整轮重跑、分段核对和撤回队列重试。
