# Memory2 P2：后台长期记忆写入与恢复

回复后任务与 Markdown 归档仍独立入队、各自推进游标。前者优先处理当前用户消息；后者照常写历史摘要和事件，但只为未完成长期提取的用户消息补提取。先完成的一方可以是归档。摘要进度、模型调用回执、长期提取覆盖是三件不同的事。

| 同一 Runtime root、消息 ID 和版本的覆盖状态 | 另一条路径如何处理 |
| --- | --- |
| written / empty / skipped | 不再调用提取模型。分别代表有有效条目、有合法空结果、候选均命中已失效条目。 |
| deferred | 本轮预算不足，没有发出提取请求；归档可接手。 |
| processing / blocked | 不代替原任务重发结果不明的调用。混合窗口中其他可处理的消息照常处理，未解决部分保留状态。 |
| withdrawn | 已撤销的来源不能再为记忆提供证据。 |

后台引用包含消息 ID 和绑定到 root、消息版本的摘要值。回读证据时校验实际返回的消息；编辑或删除后拒绝将当前文本当作旧原文。直接按消息 ID 查找仍返回当前文本。旧任务句柄仅依据原任务记录或归档快照解析；不凭相似内容猜测。归档事件保留窗口级来源；跨消息的隐式长期提取需逐项指明用户消息。来源可核对并不等于模型对原文的理解必然正确。

新增、显式替代和退休共用事务入口；每条来源的提取结果与覆盖状态一同提交。独立确认分别保留；撤销某条来源只撤销依赖它的证明、替代和退休关系。仍有独立遗忘理由时，撤销另一条纠正不能复活旧事实。归档事件不再按向量相似度合并。

**恢复兼容。** Memory2 工作流版本为 3；相同回复或回调仍使用原任务 ID。v1/v2 已完成回执保留，未完成任务在可接管时标记为 blocked，不按 v3 的步骤编号执行。新任务也不能通过另一条路径重新发送旧任务中结果不明的工作。Markdown 自身的模型步骤与草稿格式仍可恢复。记忆库绑定一个 Runtime root，挂错库时拒绝处理。不要通过清空游标、覆盖记录、模型回执或手改版本号触发重跑。

本约束适用于已连接 Runtime Event Log 的默认引擎。没有日志的兼容入口仍可写入，但不声明拥有可核验的跨路径覆盖。未回填历史记忆的陈述类型或事件时间，也没有根据旧任务的 done 状态猜测哪些来源已经成功提取。

回归入口：`tests/backend/memory2/test_write_convergence.py`、`tests/backend/memory2/test_durable_tasks_process.py` 和 `tests/backend/core/memory/markdown/test_durable_crash.py`。
