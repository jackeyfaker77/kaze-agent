# 聊天结构化块展示 v1

日期：2026-10-29。范围为桌面 Renderer 显示层，本地和远程桥接共用；不修改执行日志、模型输入、渠道发送、恢复判断、配置或 300 秒轮询。

## 事实与显示状态

- `conversationDisplay.ts` 的纯 reducer 按 `session_key` 和桥接事件 `id` 隔离实时 turn。工具由迭代号与 `call_id` 定位；重复开始事件不创建重复工具，也不覆盖已知终态。
- 当前后端的事件 `id` 与保存消息的 `metadata.request_id` 相同。远程 Host 为内部请求加客户端前缀，RPC 响应则恢复原始 ID；停止显示时只匹配对应请求，不停止同会话其他客户端的 turn。
- 历史从已保存消息投影读取。`partsFromMessage` 兼容顶层及 `extra` 字段，把工具轮次、推理和最终正文转换为同一块类型。
- `tool_chain` 只有轮次级事实。历史显示不承诺复原逐增量交错，也不伪造每个思考块的耗时。思考用时只读取 `metadata.turn_metrics.thinking_duration_ms`，缺失时不显示秒数。

## 生命周期

1. 同类型相邻增量合并；工具或正文到达时关闭前一个思考段。不同轮次和工具后出现的思考保留独立块。
2. 完成、取消、失败及断线不会直接丢弃已显示内容。缺少保存结果时保留等待历史同步的显示态，未返回的工具显示结果待核对。
3. 匹配请求身份的 assistant 历史接管后，移除该实时 turn，并记住已提交身份，忽略迟到事件。无关主动消息不清掉正在进行的 turn。
4. 取消可能仅通过 RPC 返回已保存的部分回复，没有 `chat.done`；该快照走相同接管路径。
5. `chat.delta` 无绝对偏移。断线后冻结该 turn 的增量拼接，直到权威历史接管；不通过比较字符串猜测重放重复，也不自动发送或续跑。
6. 会话切换只切换显示选择；旧 turn 不进入新会话。未解决的旧 turn 优先放在其匹配的原输入后。明确删除会话才忘记其显示缓存。

## 交互

- 执行过程默认运行时展开、结束后收起；用户手动选择优先，并尽量跨实时到历史接管保留。
- 思考、工具分别折叠，正文独立展示。工具展示原始参数、实际参数、真实状态与保存的结果预览；长内容再折叠。
- 按钮支持键盘与 `aria-expanded`/`aria-controls`；折叠内容使用 `inert`。复用现有 shimmer、grid 折叠和 reduced-motion 样式。
- 样式复用 Kaze 主题，参考 Maka 的过程/回复层次；不是复制 Maka 完整协议或跨设备运行时。

## 回归验证

```powershell
pnpm typecheck
pnpm desktop:test
pnpm --filter kaze-desktop run build:renderer
pnpm desktop:test:conversation-ui
```

纯函数和组件测试覆盖顺序、身份、迟到事件、未知状态、历史兼容、取消和重连。Electron 集成测试加载真实构建产物与模拟桥接，在独立临时用户目录验证本地/远程模式、键盘、展开状态移交、旧快照晚到、取消无 done 事件、断线与会话隔离；记录精确发送次数。

集成测试不加载真实后端、不调用模型或工具、不发 Telegram 消息，也不修改生产配置。它验证的是 Renderer 与桥接契约，不代替真实渠道验收。
