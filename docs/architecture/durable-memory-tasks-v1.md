# 回复后记忆任务持久化 v1

范围：普通对话回复后的失效主题抽取、候选记忆核对和隐式长期记忆写入。Markdown 历史归档、近期摘要及其 consolidation 回调、主动链恢复不属于本轮。已有历史不追溯触发抽取；显式记忆工具保持原契约。

## 参考与权威边界

参考 Maka 的 `packages/runtime/src/memory-extraction.ts`、`packages/runtime-host/src/server/memory-extraction-coordinator.ts`、`packages/storage/src/sqlite-long-term-memory-store.ts`：Host 负责唤醒；稳定 operation ID 与 receipt 负责识别重复；记忆写入、receipt 与推进游标在所属存储内提交。Maka 的这些机制不等于已替 Kaze 保证模型结果恢复，本实现另接入 Kaze 的 Runtime Event Log。

| 事实 | 权威存储 | 关联及提交规则 |
| --- | --- | --- |
| 原对话及准备好的抽取输入 | Runtime Event Log | `memory.post_response.prepared` 只准备任务；包含 `memory_post_response` 的 assistant 会话事实才允许接纳。两者关联原 execution turn。补存通过稳定请求身份找回原执行与已准备输入。 |
| 后台任务与领取状态 | Memory SQLite | 任务 ID = root + 原 turn + workflow v1；扫描游标与任务插入同事务。重复扫描、重复唤醒不重复入队。 |
| 模型请求及已提交结果 | Runtime Event Log | 模型执行由任务 ID + 稳定步骤路径关联；实际调用仍经过生产上下文投影器。恢复复用已提交语义结果，不使用聊天缓存猜测。 |
| 嵌入结果、检索快照与步骤回执 | Memory SQLite | 稳定步骤路径及输入摘要。已完成步骤直接复用；同一步骤输入变化则阻塞。 |
| 记忆新增、强化、合并和废弃 | Memory SQLite | 单次操作与其回执在同一 `BEGIN IMMEDIATE` 事务提交；中途退出要么全部回滚，要么一起可见。向量变更包含在该事务内。 |

记忆库不是可随意删除的投影缓存：它拥有记忆内容和副作用回执。不能只保留事件库后删除记忆库，再期待安全重跑所有写入。备份/迁移必须一起保存这些权威存储。

## 执行与恢复

Runtime 启动即发现积压；`TurnCommitted` 仅提供唤醒提示。后台每秒检查本地 SQLite，未新增任务时不调用模型。主动提醒仍是原来的 300 秒轮询，配置文件不变。

任务按源事件顺序处理。领取使用条件更新，其他 Host 必须确认旧执行者 epoch 文件锁已经释放才能接管；存活执行者不被抢占。正常停止时先取消任务，再关闭存储。

每次模型调用拥有独立执行，关联原对话与后台任务。恢复分三类：

- 结果已经提交：复用结果，即使旧进程没来得及写执行终态。
- 只有 admission、还没有网络 attempt：允许创建关联同一步骤的新 admission 后调用。
- 已有 attempt、没有完整结果：保留 `blocked`，不再次发送。这也涵盖服务端已经返回但本地尚未提交的不可判定窗口；不能承诺外部 API 的 exactly-once。

嵌入调用同样先登记开始，再保存结果；未知状态阻塞，不盲目重发。普通异常保留任务并标记 blocked，不通过每秒扫描反复调用。原对话和受控续跑不继承后台任务的上下文。未知工具结果的旧有安全边界不变。

完成任务不等于把整个批次做成一个大事务：每项记忆操作分别提交。若进程在多项操作之间退出，启动后复用已经提交的结果和回执，接着完成其余操作。工作流结构变化必须升级版本或提供迁移；v1 拒绝不支持的任务版本，不能悄悄重新解释步骤路径。

本地桥接与远程 Host 均提供只读 `memory.tasks.list`，可按 `session_key` 过滤，返回任务 ID、源事件序号、原执行 ID、状态和错误分类。该接口不领取或重试任务。本轮不增加强制重试未知结果的按钮。
