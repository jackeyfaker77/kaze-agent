# 受控续跑 v1

参考 Maka 当前恢复架构及 Phase 0 / Phase 1 安全边界契约。续跑不复活旧执行、
Provider 流或进程栈；它从已提交的完整边界创建关联新执行。旧执行事实保持不变。
不引入已退役的 reconciliation / recovery bundle writer，不将人工说明变成成功回执。

## 适用范围

v1 支持本地 Bridge 和已认证远程 Host 的普通桌面对话。Telegram、主动提醒、
独立后台任务仍由原渠道/队列持有，不从桌面旁路续跑；计划明确返回拒绝原因。
保留现有本地与远程模式、300 秒常规主动轮询和全部现有配置，不增加开关或自动续跑。

## 一个恢复判定权威

`core.execution.continuation` 从不可变事件前缀重新投影状态和模型历史。
工作台与执行入口共用判定器，UI 不提供工具安全、后台已结束等自报结论。
Host 提供实际工作区/执行目录、当前工具目录、活动执行、子任务、关联收发队列
及会话快照。未知或不能证明的情况保持阻塞。

必须满足：

- 原执行为 failed / interrupted / needs_review，且没有已关闭处置、重试或续跑；
- 具备新版 `continuation.boundary` 事实；旧历史仍能查看和重建，不伪造安全边界；
- 每次模型调用都有完整已提交响应，每个模型工具调用都有对应语义结果；
- 所有物理工具/发送结果均已确认，包括只读工具；派发后未知不能凭人工确认继续；
- 历史停在 user 或完整 tool 结果边界；完整最终 assistant 响应不再请求模型；
- 工作区和 cwd 一致，历史工具仍注册，后台和子任务已结束，关联队列均 done；
- 原执行之后没有新的会话执行，原用户消息没有被删除，确认前会话内容没有变化。

v1 对 spawn/spawn_manage 边界保守拒绝：返回 job ID 不足以证明跨进程子任务已收敛。
同样不会恢复工作区文件快照，也不能证明外部世界自边界以来没有变化。

## 计划、确认与原子领取

`execution.plan {turn_id}` 只读，返回 allowed、稳定原因、完成步骤计数、事件前缀
和计划摘要。重复调用不追加事实、不修复索引、不请求模型、不执行工具、不发消息。

`execution.continue {turn_id, plan_digest, action_id, confirmed:true}` 必须先有预览。
等待执行容量之后，重新读取前缀和 Host 安全条件，重新计算计划摘要。条件变化
则拒绝，要求重新预览；UI 不能拿旧计划绕过检查。

同一 SQLite 事务中提交新 `request.accepted`、`continuation.started` 事实和
唯一 `continuation_claims` 索引。资格按 source turn 唯一，关联原 high-water 与
prefix digest；索引可从开场事实重建。领取失败，事务整体回滚且不会调用模型。
旧执行不追加“已续跑”事件；反向关联由 claim 索引查询。

重复点击、不同 action ID、客户端重连和并发确认返回同一关联执行，不再启动。
旧计划摘要与已接纳摘要不符时拒绝。领取后即使新执行中断，也不能重新消费原资格；
可查看新执行，再由同一个判定器决定是否存在下一个安全边界。不会自动挑选续跑。

## 新请求与历史请求

普通执行首次进入工具循环时记录 `continuation.boundary` 的语义历史及工作目录。
续跑的边界使用 `continuation.started` 引用祖先，逐代校验不可变前缀和摘要；
不复制祖先执行事件，也不创建第二个原用户交互。未呈现在 UI 的原输入可通过
稳定写入 ID 补成原事实的呈现，已存在的输入不重复追加。

新执行组装当前系统提示与工具配置，消费已验证的语义历史，调用生产 Reasoner
生成下一步。模型请求依然经过原上下文投影器后才进入真实 Provider。历史请求
的精确重建是另一个只读接口，不是这次续跑请求，也不会被重新发送。

已完成的模型步骤和工具调用留在历史。历史相同工具名及规范参数再次被请求时，
在物理派发前拒绝；这不是对任意不同工具/参数之间语义等价的通用判定。
新执行不重新入队已有发送意图、不重放原渠道。完整发送回执仍归收发队列所有。

会话的模型历史在展示续跑结果时合并其祖先语义片段，并跳过旧 partial bubble 的
重复片段；UI 仍保留原始呈现。续跑执行不能走“按原输入整轮重试”来重放祖先。

## 崩溃边界

- 领取事务提交前退出：没有新执行和资格，重新预览后仍可确认。
- 提交后、模型前退出：保留一个已接纳的新执行，启动保守恢复；重复确认仅查看。
- 模型请求/工具派发后无完整结果：保留未知并拒绝续跑，不自动重发。
- 工具物理结果已提交但语义结果未提交：仍拒绝，不拼造模型工具结果。
- 完整语义工具结果后中断：用户重新预览和确认，可以创建下一代执行。
- 新模型最终响应已提交但 UI 尚未保存：结果仍在事件中；assistant 边界不再次调用模型。
- 会话呈现先提交而终态未提交：重启后呈现保留，事件重放不会追加第二份。

## 验证

测试使用临时工作区与真实 SQLite、SDK 请求边界和 Host/Bridge。模型和外部发送
仅替换网络边界，不使用现有配置或发送公网 Telegram 消息。

- 只读计划、显式确认、未知结果、旧历史/过期条件、队列所有权、多代历史去重；
- 真实 chat.send 在工具结果落盘后中断，再从工作台 RPC 续跑；
- 两个已认证远程客户端同时确认、断线重连，只产生一次新模型调用；
- 15 个实际子进程 `os._exit(73)` 故障点，包括工具/发送结果未知、物理/语义结果、
  领取事务、领取后、新模型请求/响应、会话呈现和终态。每次重新开库两次，重复
  生成计划与重建投影，模型/工具/发送计数不增长；这不是断电或文件系统 fsync 证明；
- 隔离 Electron 的真实 Renderer/preload/RPC：预览和取消无调用，确认后调用一次，
  连续点击不重复，来源和新执行可双向跳转。
